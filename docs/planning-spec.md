## 1. 목적과 사용자 요구

에이전트에게 다양한 과제와 협업 조건을 제공하고, 원하는 실험을 구성하며, 결과를 정량적으로 반복 비교하는 도구를 개발합니다. 개별 에이전트의 수행 능력과 여러 역할이 유기적으로 협력하는 능력을 함께 평가합니다.

| 사용자 요구 ID | 요구사항 | 대응 기능 |
| --- | --- | --- |
| U-01 | 과제 평가를 전문적으로 수행하고 정량적으로 계속 재사용합니다. | 평가 기준 버전 관리, 증거 기반 판정, 반복 실행과 회귀 비교 |
| U-02 | 다양한 성능평가 과제를 다룹니다. | 교체 가능한 과제 묶음과 과제별 평가 모듈 |
| U-03 | 과제를 협력해서 처리하는 파이프라이닝을 평가합니다. | 단계·역할·의존성·인계 계약과 전체 목표 평가 |
| U-04 | 과제와 조건을 주입해 원하는 실험을 수행합니다. | 실험 명세, 주입 트리거, 적용 기록, 대조 조건 |
| U-05 | 기존 모듈화 프로젝트와 연결하고 린하게 개발합니다. | 독립 평가 코어, 실행 어댑터, 단계별 완료 기준 |

위 요구와 README의 방향성을 제품 기준으로 사용합니다. 아래의 상태 이름·논리 데이터 항목·단계 구분은 이를 구현 가능한 형태로 구체화한 설계안입니다. 직렬화 형식과 API의 최종 확정은 구현 설계에서 진행합니다.

## 2. 사용 주체와 핵심 흐름

초기 사용자는 로컬에서 에이전트 시스템을 개발·평가하는 실험자입니다. 같은 사용자가 과제 작성과 결과 검토를 수행할 수 있으며, 독립 평가 여부는 별도로 기록합니다.

1. 과제 묶음과 기준 버전을 선택합니다.
2. 가설, 기준 실행, 변경 조건, 반복 횟수와 예산을 정의합니다.
3. 실행 대상의 기능과 입력·평가 자료 분리를 사전 검증합니다.
4. 기존 기록을 가져오거나 실행 어댑터를 통해 새 실험을 수행합니다.
5. 단계별 증거와 주입 결과를 수집합니다.
6. 규칙 검사와 의미 평가를 수행하고 미확정 판정을 검토합니다.
7. 과제별·반복별·조건별 결과를 비교하고 보고서를 생성합니다.
8. 기준 변경 시 기존 증거를 재평가하거나 새로운 실험으로 분리합니다.

저장된 증거만으로 평가하는 경로는 실행 시스템과 모델 호출 없이 동작해야 합니다.

## 3. 범위와 책임

### 3.1 첫 버전

- 과제 묶음 등록·검증과 외부 과제 버전 참조를 지원합니다.
- 단일 수행과 고정된 작성→검토→조건부 수정 흐름을 지원합니다.
- 저장된 증거 가져오기와 하나의 실제 실행 어댑터를 지원합니다.
- 단계 경계의 자료 추가와 도구 실패 주입을 지원합니다.
- 규칙 평가, 교체 가능한 의미 평가, 사람의 판정 확정을 지원합니다.
- 반복 실행·재평가·기준 실행 비교와 기계 판독용 및 사람이 읽는 보고서를 제공합니다.
- 작은 두 과제 묶음으로 재사용성을 검증합니다.

### 3.2 후속 확장

병렬 분담과 통합, 상충 결과 조정, 요구사항 변경, 인계 누락 주입은 후속 범위로 둡니다. 첫 계약은 단계와 의존성을 표현하되 미지원 실행 형태를 조용히 순차 실행으로 바꾸지 않습니다.

웹 UI, 분산 실행, 상주 스케줄러, 동적 팀 생성, 자동 자기 개선, 대규모 과제 카탈로그는 첫 버전에서 제외합니다.

### 3.3 시스템 경계

| 시스템 | 책임 |
| --- | --- |
| agent-eval | 실험 정의·반복 요청·주입 계획·증거 정규화·평가·비교 |
| role-orchestrator 등 실행 시스템 | 단계 스케줄링·업무 흐름·인계·재개와 실제 주입 지점 제공 |
| role-runtime | 워커·역할 상태·실행 영수증·산출물 |
| codex-adapter | Codex 호출·세션·프로토콜 실패 정보 |
| 과제 제공 프로젝트 | 도메인 과제·평가 기준·자료 출처 |
| 선택적 관측 서비스 | 추적·조회·시각화 |

실행 어댑터는 기능 지원 여부와 버전을 선언합니다. 평가 코어는 대상 프로젝트의 내부 패키지나 특정 관측 서비스에 의존하지 않습니다. 실행 시스템에 없는 수정 루프나 주입 지점은 별도 연동 개발 사항으로 기록합니다.

## 6. 협업과 주입 동작

### 6.1 첫 협업 시나리오

작성자는 제공된 자료와 산출물 계약을 받아 문서를 생성합니다. 검토자는 지정된 자료와 결과를 검토하고 수용·수정 요청·판단 보류를 반환합니다. 수정 요청이 있을 때만 명세에 정한 횟수 안에서 수정합니다. 수정 후 판정은 별도 검토 단계에서 수행합니다.

검토 단계의 수용 의견은 평가 대상의 행동입니다. 최종 성능은 agent-eval의 별도 기준으로 판정하며, 수용 의견 자체를 정답으로 취급하지 않습니다. 불필요한 수정도 측정 가능하도록 올바른 초기 결과를 포함한 과제를 구성합니다.

### 6.2 주입 계약

첫 버전의 주입 트리거는 안정적인 단계 경계와 지정된 도구 호출입니다. 실행 중 임의 시점의 프로세스 조작은 범위에 포함하지 않습니다.

주입은 예정·적용·미적용·적용 오류로 구분합니다. 목표 단계에 도달하지 못한 실행은 미적용 사유를 남깁니다. 재개 후 중복 적용을 방지하려면 주입 ID와 적용 기록을 실행 시스템이 확인해야 합니다. 확인할 수 없는 경우 적용 여부를 불확실로 기록합니다.

도구 실패는 해당 실행 어댑터가 지원하는 모의 응답 또는 실패 지점으로 한정합니다. 실제 인증·권한·네트워크 설정을 변경하지 않습니다. 대조 실행에는 동일한 원본 과제와 주입 없는 조건을 사용합니다.

## 7. 상태와 실패 처리

실행 상태와 평가 상태는 서로 독립적으로 기록합니다.

- 실행: 준비·실행 중·완료·실패·중단·실행 여부 불확실을 구분합니다.
- 항목 판정: 충족·미충족·판단 불가·해당 없음을 구분합니다.
- 평가 처리: 대기·완료·평가기 오류를 구분합니다.
- 판정 확정: 초안·확정과 검토 이력을 구분합니다.

전체 성공은 실험 전에 지정한 필수 기준의 충족 여부로 결정합니다. 필수 기준이 판단 불가이거나 평가기 오류이면 성공으로 확정하지 않습니다. 과제 자체가 자료 부족 판단을 요구한 경우에는 올바른 보류 응답이 과제 성공이 될 수 있습니다.

실행 상태가 불확실하면 새 모델 호출을 자동 발행하지 않습니다. 재시도 허용 범위는 실행 대상의 계약과 실험 명세를 따릅니다. 평가기 오류의 재시도는 모델 과제 재실행과 분리하며 각각의 비용을 기록합니다.

예산은 실행 대상 예산과 평가 비용을 구분합니다. 강제 상한인지 관측 목표인지 명시하며, 미지원 강제 상한은 검증 단계에서 거부합니다. 상한에 도달하면 새 실행 요청을 중단하고 진행 중 작업은 어댑터가 보장하는 제어 범위와 실제 종료 결과를 기록합니다.

## 8. 지표와 비교 규칙

| 지표 | 기본 정의 |
| --- | --- |
| 전체 성공률 | 성공 확정 반복 수 / 사전 계획된 반복 수. 미실행·중단·불확실 건수를 함께 표시합니다. |
| 판정 가능 범위 성공률 | 성공 확정 반복 수 / 최종 성공·실패 판정 가능 반복 수. 전체 성공률과 별도 표시합니다. |
| 항목 충족률 | 충족 항목 수 / 해당 실행에 적용되는 평가 항목 수. 판단 불가와 평가 오류를 별도 계수합니다. |
| 필수 정보 인계율 | 전달이 확인된 필수 정보 항목 수 / 사전 정의된 필수 정보 항목 수 |
| 복구 성공률 | 복구 성공 실행 수 / 주입 적용이 확인된 실행 수. 주입 미적용·불확실은 별도 표시합니다. |
| 평가자 불일치율 | 판정이 다른 공통 평가 항목 수 / 양쪽의 유효 판정이 있는 항목 수 |
| 기준 판정 일치율 | 기준 판정과 일치한 항목 수 / 비교 가능한 확정 기준 항목 수 |
| 오탐·미탐 | 이진 충족 판정에서 오탐률은 FP/(FP+TN), 미탐률은 FN/(FN+TP)로 정의합니다. |
| 시간·토큰·비용 | 작업 실행과 평가를 분리하고 측정 범위·단위·누락·추정 여부를 표시합니다. |

분모가 0인 비율은 값 없음과 사유로 표시합니다. 해당 없음은 적용 항목에서 제외하되 건수를 표시합니다. 초안 판정 기반 결과는 잠정 결과로 표시합니다.

동일 과제·자료·기준의 버전, 비교 대상 조건, 예산 정책을 확인한 뒤 비교합니다. 계획한 변경 변수 외의 차이는 교란 가능성으로 명시합니다. 기준 변경 후 비교하려면 양쪽 증거를 같은 기준으로 재평가합니다. 필요한 증거가 없으면 직접 비교를 제한합니다.

과제별 결과와 과제 묶음의 요약을 함께 출력합니다. 묶음 평균의 가중 방식과 제외 규칙을 명시하고 전체 원시 건수를 보존합니다. 반복별 분포와 표본 수를 표시하며 소수 표본만으로 성능 우위를 확정하지 않습니다.

## 9. 비기능 요구사항

| ID | 요구사항 | 확인 방법 |
| --- | --- | --- |
| NFR-01 | 로컬에서 평가와 보고가 가능해야 합니다. | 저장된 증거와 규칙 평가만으로 네트워크 없이 보고서를 생성합니다. |
| NFR-02 | 원본·판정 이력을 보존합니다. | 재가져오기·재평가·중단 후 원본 해시와 이전 판정을 대조합니다. |
| NFR-03 | 외부 의존성을 어댑터로 격리합니다. | 코어의 import 경계와 실행/평가기 대체를 검증합니다. |
| NFR-04 | 비공개 자료와 정답의 노출을 통제합니다. | 수행 입력과 공개 보고서에 포함되는 항목을 검증합니다. 원문 외부 전송은 선택한 연동 설정에 명시합니다. |
| NFR-05 | 불완전 기록을 숨기지 않습니다. | 누락·충돌·미지원 버전·손상된 참조를 주입해 오류와 집계 제외 사유를 확인합니다. |
| NFR-06 | 외부 모델을 부르지 않는 기본 검증 경로를 제공합니다. | fixture로 계약과 실패 경로를 검사하고 실제 모델 검증은 별도로 기록합니다. |

처리량·대규모 저장 용량·지연시간 목표 수치는 초기 사용량을 측정한 뒤 정합니다. 실행 어댑터의 OS 제약과 평가 코어의 지원 환경은 따로 명시합니다.

## 10. 단계별 산출물과 완료 조건

| 단계 | 산출물 | 완료 조건 |
| --- | --- | --- |
| M1: 증거 기반 평가 | 최소 계약·기록 importer·규칙 검사·판정 이력·보고서 | 정상/누락/충돌 기록을 구분하고 같은 증거의 재평가와 조건별 비교가 가능합니다. |
| M2: 평가 신뢰성 | 의미 평가 어댑터·검토 기록·기준 사례·신뢰성 보고 | 원래 판정을 보존하며 사람의 기준과 비교합니다. 사람의 기준이 없으면 이 단계의 신뢰성 검증은 미완료입니다. |
| M3: 실행과 주입 | 첫 실행 어댑터·단독/협업 반복·자료/실패 주입 | 실제 실행에서 조건 적용과 결과를 확인하고 미적용·중단·불확실 경로도 보존합니다. |
| M4: 재사용 검증 | 두 번째 과제 묶음·공통 CLI·회귀 사례 | 공통 엔진 수정 없이 과제를 연결하고 전체 첫 버전 완료 기준을 확인합니다. |

첫 버전은 M1~M4 완료로 정의합니다. fixture 통과, 실제 모델 실행 성공, 평가 신뢰성 확인을 각각 기록합니다. 아직 구현된 기능과 통과한 검사는 없습니다.

## 11. 미확정 사항과 결정 시점

| 항목 | 결정 시점 |
| --- | --- |
| 파일 형식·저장소·정확한 스키마와 CLI 명령 | M1 계약 설계 |
| 첫 과제의 내용·사람이 확정할 기준 사례·평가자 구성 | M2 기준 조율 |
| 첫 실행 어댑터의 공개 계약·수정 루프·주입 지점 | M3 연동 설계 |
| 실제 모델·반복 횟수·비용 예산·합격 임계치 | 각 실험 실행 전 |
| 두 번째 과제 묶음의 도메인 | M4 착수 전 |
| 성능 목표 수치·병렬 시나리오 확장 순서 | 첫 사용 결과 검토 후 |

미확정 사항은 현재 문서 작성의 장애가 아닙니다. 실제 실행과 판정에 영향을 주는 값은 해당 단계에서 확정하고, 사용자의 기존 선택과 권한 범위를 유지합니다.
