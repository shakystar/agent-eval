## 독립 반례 검토

상류의 설계 판정에 동의한다. 공통화할 것은 허용 목록의 구현이 아니라 경계별 기대값을 담은 시험 벡터다. 일반 roster는 모델 별칭만, 계획 카탈로그는 별칭과 정규명 모두를 받는다. Go 브리지는 명시한 모델에는 정규명만 허용하며, 모델·effort 플래그를 생략하면 해당 값 검사를 건너뛰지만 명시적 빈 값은 거절한다. 한쪽에만 새 effort를 허용하는 결함을 넣었을 때 정규명 입력의 수락·거절 차이를 검출해야 한다. 승인 검사 분리는 조건부다. context 없는 계획 생성은 실행 승인이 아니다. 실제 실행 진입점에서 context가 없거나 UID·팀·목표가 승인과 맞지 않을 때 제출이나 상태 변경이 한 번이라도 발생하면 실패로 판정한다. 인덱스 추가는 병목 근거가 없어 기각한다. 현재 검증 범위는 선택된 팀의 모든 멤버·목표다. 검사를 사용 항목으로만 좁히는 결함을 넣어 미사용 멤버의 잘못된 바인딩이나 미사용 목표의 잘못된 승인이 수락되면 실패다.
다음 단계는 패치 공개 전에 이 기대값과 재조회 관측 구간을 고정하는 것이다. 재조회 경로에 중복 제출을 넣어 같은 바이트의 영수증 파일 하나만 남기는 반례에서는 파일 수와 해시가 같아도 재조회 시작부터 종료까지 추가 제출이 1건이면 실패다. 완료 턴 수도 별도로 대조한다. 사용량 누락은 uncertain, 명시적 0은 verified인지 원본 영수증으로 구별하고 M3 종료·잠금·커밋 마커 사례도 재검증한다. 이는 관측된 후보 결함이 아니라 시험할 반례다. 실행 경로의 제출 전 승인 책임, G 인수 기준과 정책 전체 SHA, 후보 전체 SHA·빌드 해시 및 동일 조건의 기준·후보 실행 영수증과 검증기 원본 결과는 미확인이다. 판정 범위는 설계 권고에 한하며 구현·실측·출시 승인이 아니다.
