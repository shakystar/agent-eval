# 기획 근거와 개발 실사

## 연구 질문과 인계

같은 하위 모델에서 역할 계약만 바꾸면 제한된 관측의 과보류나 근거 없는 추론의 오통과가 달라지는가? 연구팀은 관측·초안·독립 반증·종합을 거쳐 현재 자료로 계약 채택과 운영 모델 하향을 결정할 수 없다고 인계했다. 이전 Astra 실험은 하나의 역할 계약에서 추론 수준을 비교했다. Sol/high 보정 두 사례에서는 두 계약이 같은 방향으로 답했지만 공개 보정 사례의 결과로 계약 동등성을 입증할 수 없다. 두 실험의 분모를 합산하지 않는다.

| 1차 연구 | 가져올 방법 | 적용 한계 |
|---|---|---|
| [FrugalGPT, Chen 외](https://arxiv.org/abs/2305.05176) | 여러 모델의 호출 비용과 품질을 실제 업무 분포에서 함께 비교한다. | 논문의 캐스케이드와 프로젝트의 고정 역할 라우팅은 다른 설계다. 논문 수치를 비용 목표로 전용하지 않는다. |
| [RouteLLM, Ong 외](https://arxiv.org/abs/2406.18665) | 강·약 모델의 선택을 평가 데이터와 연결하고 모델 쌍 교체 후 재검증한다. | 선호 데이터로 학습한 동적 라우터의 결과는 이 연구 검토자의 두 계약에 대한 효과 크기를 제공하지 않는다. |

연구자가 제시한 동등성 범위와 절대 품질 하한은 운영 전환을 검토할 때 사전 정의한다. 소규모 탐색에서는 관측된 차이, 관측된 동점, 기술 실패를 구별한다. 비용 절감 보장, 학습형 라우터 도입, 자동 모델 강등을 전제하지 않는다.

## 검증한 출발점

- Python의 `contracts.py`가 별칭과 지원 경로를 정의한다. `roster.py`의 명부 행은 별칭을 요구한다. `planning_catalog.py`는 별칭과 정식 ID를 처리한다. `handoff_runner.py`와 `runtime.py`도 같은 검증 함수를 호출한다. 입력 형식 차이는 기존 호출자 계약의 일부다.
- Go 브리지 `cmd/runtime-bridge/main.go`의 도움말과 검증에 기존 두 모델이 열거돼 있다. 현재 바이너리에 `--model gpt-6-luna --reasoning-effort high`를 제출한 정적 사전 시험은 종료 코드 1로 경로를 거부했다. Python도 해당 조합을 거부했다. 이 시험은 신규 모델 성공 경로 검증이 아니다.
- 어댑터 기준 소스의 `adapter.go`에서 모델은 스레드 시작, effort는 턴 시작에 들어간다. 초기화 시 빈 값과 low·medium·high를 처리한다. 어댑터 동작을 먼저 합성 peer로 확인하고 변경 필요성이 재현될 때만 수정한다.
- 계정의 로컬 모델 목록에서 `gpt-6-luna`와 `gpt-5.6-luna` 및 high 설정이 관측됐다. 두 ID는 예비 후보이며 버전 번호만으로 업무 능력·가격 순서를 확정하지 않는다. M0에서 지원 상태를 재조회하고 각 단계에서 반환된 세션·턴을 대조한다. 이번 기획에서 두 모델에 실제 업무를 배정한 횟수는 0회다.

## 코드 리뷰 후속 작업 선정

| 항목 | 현재 근거 | 개발과 리뷰의 역할 |
|---|---|---|
| 라우팅 규칙의 변경 위치 | Python 경로 판정, Go 검증·도움말이 각각 모델 목록을 표현한다. 기존 두 별칭의 성공은 정상 동작이다. | 지원 모델·effort의 정규 표와 소유자를 먼저 정한다. 언어별 구현을 같은 공용 사례로 대조하고 승인되지 않은 조합의 실제 제출 0회를 센다. 이 경계를 견본 모듈로 삼는다. |
| 기존 리뷰 지적의 선별 | M2의 사용량 누락/명시적 0, M3의 종료 기록·잠금·확정 마커는 수정·인수됐다. | 다시 열린 결함으로 집계하지 않는다. 수정 전후 계약표와 회귀 기준으로 재사용한다. 남은 책임 혼합이나 오류 경로 중복은 현재 코드 위치·정책 조항·구체적 영향이 재현될 때만 별도 작업으로 채택한다. |
| 공통 정책과 언어 관례 | 기존 개발 정책이 명명, 책임, 직렬화, 복구, 오류, 검증 조항과 언어별 검사법을 제공한다. | 지적마다 근거 SHA·조항·소유 레포·관찰값·통과 반례를 기록한다. Go는 기존 오류 타입·패키지 경계와 gofmt/vet/test, 동시성 변경 시 race를 검증한다. Python은 자원 정리와 외부 계약을 unittest와 공개 CLI로 확인한다. 줄 수나 클래스 수만으로 재작업을 요구하지 않는다. |
