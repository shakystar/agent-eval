# v0.3.3 M0 시험 규약

연구팀 독립 검토자 acl-025가 고정 근거와 고정 초안을 검토하는 업무를 대상으로 한다. 개발팀은 경로 벡터와 합성 원장만 받는다. 인수 담당자가 보관한 묶음에는 사례별 입력·정답, 상세 채점 기준, 실행 순서, 익명 표시 순서가 있다. 운영 명부는 현행을 유지한다.

## 채점과 배정

- 두 팔은 동일한 합성 입력·초안, 새 격리 세션, 같은 도구 권한(외부 도구 없음), 모델과 high effort를 사용한다. 새로운 관측이나 재현 기록이 없는 경우 제공된 자료의 범위 안에서만 판정한다. 원작성자와 검토자를 별개로 배정한다. 작성자 또는 참여 이력 확인 실패 시 독립 검토 완료를 주장할 수 없다.
- 첫 체급은 gpt-6-luna/high다. 매 슬롯에 실제 모델·effort·캐시 관측과 최초 입력 해시를 기록한다. 입력·모델·effort·권한 등 비교 조건 불일치, 중복 제출, 턴 누락은 유효 쌍에서 제외하고 추가 호출을 중단한다. 사용량 비교에 필요한 캐시 관측이 불충분하면 비용 우위는 미확인으로 둔다.
- 사례별 여섯 gold 필드는 평가 근거다. 판정 단위는 사례 × 계약 × 네 축(중요 오류 누락, 근거 없는 단정, 관측과 추론의 혼동, 필수 보완 요청 누락)이다. 각 축에 pass/minor/critical과 해당 출력·근거 위치를 잠근다. 중요 사실을 뒤집거나, 근거가 없는 실행·채택·검증 완료를 확정하거나, 금지된 결정을 승인하는 오류는 critical이다. 사례별 중요 반례에 해당하지 않는 국소 오류는 minor다. 부수적인 점수 합산은 네 축의 중단·우위 판단에 사용하지 않는다.
- 현행 먼저 4건과 후보 먼저 4건을 배정한다. 블라인드 판정자에게는 입력·정답·익명 응답만 전달한다. 계약명·실행 순서·대응표는 분리하고 채점 잠금 후 공개한다. 두 번째 체급은 같은 8건·동일 통제로 별도 라운드를 구성한다.
- 1차 16슬롯, 실패 포함 전체 32회 상한, 자동 재시도 0회다. 한 건의 중요 오류 또는 같은 계약·같은 비중요 축에서 서로 다른 두 사례의 결함이 확인되면 추가 제출을 중단한다. 중요 오류 확인은 블라인드 중간 판정으로 수행하고 다음 슬롯 제출 전에 종료 신호를 확인한다. 미실행과 무결함을 구분한다.
- 양쪽 기준 통과 및 8/8 유효 쌍이 전제다. 네 축 모두 악화 없이 서로 다른 2건 이상 개선된 경우에만 파일럿 우위 신호로 남긴다. 모든 축의 대응 판정이 0/32 불일치이고 양쪽 기준을 통과할 때만 추가 체급의 가용성·체급·비용 순서·시험 권한을 확인한다. 양팔이 동률이어도 2차 실험을 자동으로 시작하지 않는다.

## 인계와 보관

M1은 실험용 경로의 명시 설정, 거부 시 제출 0회, 기존 호출자 호환성을 구현한다. M2는 같은 벡터를 사용해 코드 정책 근거와 동작 보존을 검토한다. 두 단계가 같은 파일을 수정하는 변경은 직렬화한다. 실제 종단 영수증·비용·계약 우위는 후속 시험에서 검증한다.

M0-sealed.json의 ciphertext와 nonce는 Base64이며 AAD는 파일의 aad 값을 UTF-8로 해석한다. AES-256-GCM 복호화 키는 M0 실행 호스트의 기획팀 전용 상태 디렉터리에 별도로 보관한다. 인수 담당자가 복호화한 바이트의 SHA-256을 M0-manifest.json과 대조한 후 슬롯별 최소 정보만 전달한다. 개발팀 입력이나 Git에는 키를 넣지 않는다.
