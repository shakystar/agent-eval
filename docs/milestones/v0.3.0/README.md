## 개발 및 리뷰 비교

후보 실행 전 확정한 개발 대조 과제는 기존 test_development_acceptance의 패치·시험 실행 및 영수증 연결이고, 리뷰 대조 과제는 기존 test_review_team의 정상 최소 경로·자기 검토 차단·보완 시 최종 인수 중지다. 전체 fixture 회귀는 동결 기준과 최종 후보에서 각각 한 번 수행한다. 실패 시 진단 재실행을 별도로 표시한다. fixture의 분기 통과와 실모델의 결함 탐지율은 별개로 집계한다. 독립 검토에는 해당 사례의 기대 판정을 입력하지 않는다.

최초 제출·수정본·결과·거절 근거·소요 시간은 확보한 실행 기록에서 산출한다. 동일 과제의 비교 가능성, 최종 인수 통과 여부, 누락 관측값을 함께 기록한다. 품질 편차 조사용 추가 반복은 대표 사례당 1회까지로 잡고 M5까지 확보한 편차를 후속 v0.3.1에 넘긴다.

## 통합 인수 시나리오

- 팀과 목표만 주어진 명확한 과제에서 필요한 인력이 선택되고 검증된 영수증이 남는다.
- 의도에 따라 범위가 달라지면 사용자 확인 또는 원작성자 보완 단계로 돌아간다.
- 기획팀이 직접 만든 연구팀 계약을 개발팀·리뷰팀이 독립적으로 인계받고 개정 및 근거를 추적한다.
- 의뢰 기반 연구와 선제 신호가 모두 기획팀의 근거 있는 제품 결정에 도달한다. 반증과 근거 부족도 보존한다.
- 기존 필수 경로와 재조회 계약이 유지된다. 제품 품질 편차는 관찰하되 필수 인수 실패와 구분한다.
