# M2 · 세 저장소 통합 재현과 독립 인수

2026-11-25 기준으로 다음 작업 범위를 확정했다. M1에서 독립 인수한 로컬 합성 후보를 모두 같은 이름의 브랜치 `candidate/v0.3.2-m1`에 게시했다. M2의 시험 대상을 아래 커밋 조합으로 고정한다.

| 저장소 | 시험 커밋 |
|---|---|
| codex-adapter | [f338b29](https://github.com/shakystar/codex-adapter/commit/f338b2908ff32094514763000bf71da4d7d4bcaf) |
| role-runtime | [4a457bb](https://github.com/shakystar/role-runtime/commit/4a457bb576376366989ad6d53ed291f59848d4a0) |
| role-orchestrator | [3ad85d3](https://github.com/shakystar/role-orchestrator/commit/3ad85d35d19843a436f667327a22621696f1ff03) |

M1에서 영수증 재전달, 동일 출력의 독립 실행, 근거 유실, 배정·역할 불일치를 합성 환경에서 검증했다. Python 32개 모듈 156건과 Go 후보 검사를 통과했고, 이서진과 강이현이 수정본을 인수했다. 사용량의 관측 단위는 같은 턴에서 마지막으로 일치한 사용량 알림이다. 제공자 내부 호출 수와 총 과금량은 미확인이다. [M1 인수 원문과 후보 조합](m1-candidate-acceptance.json)

| 순서 | 담당과 입력 | 인계 산출물과 통과 조건 |
|---|---|---|
| 1. 독립 재현 | 오케스트레이터가 검증팀에 세 SHA와 M0 기준표를 전달한다. | 깨끗한 체크아웃에서 어댑터와 런타임을 함께 빌드하고 후보 브리지로 Python 검사를 실행한다. 실행 명령, 실제 세 SHA, 바이너리 식별값, 결과를 기록한다. |
| 2. 장애·호환성 | 개발팀이 합성 사례와 재개 지점을 제공하고 독립 검증팀이 실행한다. | 중복 전달, 출력이 같은 별도 턴, 반환 유실 후 재개, 타 배정·구개정의 상태와 사용량을 배정별로 대조한다. 실행 미상은 자동 재호출 0회다. v0.3.0·v0.3.1 기록은 원래 판정을 유지하고 신규 증빙 필드는 미확인으로 읽는다. |
| 3. 두 연구 경로 | 검증팀이 사용자 의뢰와 선제 신호를 각각 고정 후보에 입력한다. | 사례별 배정·시도·턴·영수증·초안 개정·최종 결정이 같은 출처로 연결돼야 한다. 작성자가 검토자로 배정되면 호출 전 차단하고, 자발 신고는 보존·재배정한다. 누락은 미확인, 다른 출처의 결정 연결은 실패로 기록한다. |
| 4. 독립 판정 | 리뷰팀이 M0 기준과 각 실행의 근거를 대조한다. | 기준별 기대값·관측값·근거·판정을 표로 제출한다. 서명·키 검증 등 증빙이 없는 항목은 보류 사유와 책임자를 명시한다. 보완 시 작성자에게 역요청하고 변경한 SHA 조합으로 영향 항목을 재검증한다. |

첫 작업은 1번 독립 재현이다. M2 결과는 프로젝트 레포의 이 마일스톤 디렉터리에 남긴다. 합성 시험으로 해소되지 않는 질문은 목적과 관측값을 정해 소규모 진단으로 확인한다. M3 역할 비교의 표본과 예산은 M2 인수 결과와 실측 사용량을 보고 별도로 결정한다. 운영 키 발급, 배포 및 main 병합은 별도 결정 사항이다.
