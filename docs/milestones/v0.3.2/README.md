## 목표와 시작점

리뷰 하나가 어느 초안 개정에 어떤 자격으로 배정됐는지 증명하고, 기술 실패를 보존하면서도 역할 계약의 품질을 비교할 수 있게 한다. 연구팀의 관측·초안·독립 검토 3인 구성과 모델 배정은 고정한다. 사용자 의뢰와 선제 신호 경로를 모두 다룬다. 컨텍스트 메모리는 v0.4.0의 별도 범위다.

v0.3.1에서 현행 리뷰는 최초 8회 중 7회가 유효했고 관찰 과보류가 3회였다. 후보는 8회 모두 유효했고 과보류가 없었다. 양쪽의 유효 리뷰에서 근거 없는 추론의 오통과는 없었다. 현행의 초안 해시 복사 실패 1회와 별도 선제 신호의 독립성 확인 보류 때문에 최종 독립 인수팀은 현행 계약을 유지했다. 사후 보완은 최초 결과와 별도로 보존했다. [v0.3.1 독립 인수 원본](https://github.com/shakystar/agent-eval/blob/a3d386b1ab6485405fa0f3a7c94a268c50994c35/docs/milestones/v0.3.1/verdict.json)

현재 오케스트레이터에는 작성 참여자 대조, 배정 전 체크포인트, 네이티브 영수증 검증이 이미 있다. 이번 설계는 기존 연결을 재사용하고, 리뷰 단계에서 모델이 초안 해시를 옮겨 적는 부분과 모델이 읽을 수 있는 검토자 신원 경계를 다룬다. [현재 연구 인계 코드](https://github.com/shakystar/role-orchestrator/blob/3c7af3f464c652a27be9843a45dc418f1168e820/role_orchestrator/research_handoff.py) · [현재 영수증 대조 코드](https://github.com/shakystar/role-orchestrator/blob/3c7af3f464c652a27be9843a45dc418f1168e820/role_orchestrator/planning_team.py)

## 개발 인계

| 단계 | 주관과 입력 | 인계 산출물과 통과 조건 |
|---|---|---|
| M0 · 계약과 평가 규약 동결 | 기획팀·독립 인수팀. 위 소스 조합, 과거 원본, 현행·후보 역할 본문을 대조한다. | 필드별 신뢰 원천, 상태 전이표, 고정 커밋, 호출 수 관측 지점, 독립 채점표, 재시도 적격 사유와 마감 시각을 고정한다. 숨김 사례는 후보 작성자와 분리한다. |
| M1 · 배정과 실제 실행 연결 | 오케스트레이터 담당은 불변 초안과 배정 원장을, Go 런타임 담당은 검토자 신원과 호출·영수증을 맡는다. | 동일한 배정 ID에 초안 개정·해시, 검토자 ID·역할 버전, 시도와 결과를 결합한다. 모델에는 검토 대상과 본인 ID를 읽을 수 있게 전달한다. 의견·근거·자발 신고는 모델이 작성한다. |
| M2 · 인프라·호환성 인수 | 개발팀과 독립 검증팀. M1의 배정·실행 계약을 기준으로 결함을 주입한다. | 아래 반례의 기대 상태와 실제 호출 수가 전부 일치해야 A/B로 넘어간다. 원본 기록을 읽는 호환 시험과 중단 후 재개 시험을 포함한다. |
| M3 · 역할 계약 비교·최종 판정 | 독립 인수팀. M2를 통과한 같은 경로에서 현행과 후보를 비교한다. | 최초 상태표·주장별 품질표·복구표와 양팔 대응쌍을 제출한다. 의뢰·선제 신호의 종단간 영수증은 통제 실험과 분리한다. 인프라 적합성과 역할 계약의 채택·유지·판정불가를 구분해 최종 권고한다. |

권태린이 선택한 증빙 계약에서는 오케스트레이터가 논리 배정과 그 안의 시도를 식별한다. Go 런타임은 실제 전달할 초안 바이트의 해시와 적재한 역할 본문을 대조하고, 호출 관찰값과 결과 다이제스트를 포함한 네이티브 영수증에 서명한다. 오케스트레이터가 신뢰 키·스키마·배정 원장·결과를 대조해 현재 개정에 한 번만 확정한다. 기존 영수증의 해시만으로 이 서명 요건을 충족했다고 간주할 수 없다. 구현 전에는 실제 키 관리와 호출 확인 경계를 확인해야 한다.

### 인프라 인수 시나리오

아래 항목은 모두 **미실행**이다. 판단 대상은 최종 파일, 배정 원장, 네이티브 실행 관측과 영수증의 연결이다.

| 시나리오 | 기대 결과 |
|---|---|
| 정상 배정 후 원문 개정 | 검토 개시 시 초안을 고정한다. 저장 직전에 개정이 바뀌면 예전 결과는 격리하고 새 개정에 붙이지 않는다. |
| 다른 배정·다른 검토자·역할 버전 불일치 | 모델이 그럴듯한 ID나 해시를 반환해도 결과를 확정하지 않는다. 네이티브 결과의 실제 주체와 배정 시점의 원천 정보를 대조한다. |
| 전달 중복과 실제 이중 실행 | 동일 영수증을 재전달하면 결과 조회로 끝난다. **동일 출력을 생성하는 실제 호출을 두 번** 주입하면 출력 파일이 같아도 호출 수 2로 실패해야 한다. 같은 키의 서로 다른 결과는 충돌로 격리한다. |
| 확정 전 중단·응답 유실 | 이미 성공한 시도는 영수증을 조회해 이어간다. 실행 여부를 알 수 없으면 미상으로 두고 원장과 대사한다. 자동 재호출 횟수는 0이어야 한다. |
| 실제 자기 검토·자발적 이해충돌 | 명단 대조에서 작성 이력이 확인되면 검토 진입을 차단한다. 명단을 통과한 뒤의 자발 신고도 보존하고 재배정에 연결한다. 정당한 안전 보류로 기록한다. |
| 신원·작성자 원천 불충분 | 확인된 충돌로 집계하지 않는다. 신원 대조 불능으로 중단하고 보완할 원천과 책임자를 남긴다. |
| v0.3.0·v0.3.1 기록 | 당시 스키마와 판정으로 조회한다. 새 필드가 없으면 미확인으로 표시한다. 재평가는 원본과 분리해 연결한다. |

### 역할 계약 평가 규약안

미공개 합성 **16사례**를 진행 정답 8개, 보류 정답 8개로 구성한다. 사례당 2회씩 양쪽 계약에 배정하면 **최초 64배정, 팔당 32배정**이다. 독립 사례 수는 16개다. 양팔의 모델·추론 설정, 입력, 초안과 인프라 개정은 같게 고정하고 실행 순서를 교차한다. 인수팀은 팔 라벨을 가린 채 평가하고 채점 근거를 잠근 뒤 라벨을 공개한다.

| 지표 | 분모와 기록 원칙 |
|---|---|
| 최초 유효성 | 팔별 예정 32건 전체. 최초 마감 시점의 유효·정당한 안전 보류·기술 실패·미완료를 나눠 기록한다. 미시작과 실행 미상을 분모에서 빼지 않는다. |
| 의미 품질 | 진행 정답의 최초 유효 결과에서 과보류를, 보류 정답의 최초 유효 결과에서 오통과를 센다. 각 군의 누락과 양팔 유효 대응쌍을 함께 공시한다. |
| 복구 | 복구율의 분모는 최초 기술 실패 전체, 분자는 같은 배정에서 복구 마감까지 유효 확정한 건수다. 분모가 0이면 해당 없음으로 표시한다. 재시도 적격·부적격·미상과 실제 재호출·기존 결과 재사용을 구분한다. 최초 배정당 재시도 최대 1회. 양팔 추가 진단은 최대 2쌍이며 최초 점수나 최종 판정을 바꾸지 않는다. |

**판정 순서 제안**

1. 인프라 필수 시험에서 명백한 불합격이 있거나, 신뢰 가능한 후보 최초 결과에서 오통과가 1건이라도 있으면 현행을 유지한다.
2. 인프라 증거 부족, 동결 위반, 호출 수 대사 불능 또는 표본 부족이면 **판정불가**다. 양팔 각각 최초 유효 30/32 이상, 정답군별 15/16 이상, 군별 양팔 유효 대응쌍 14/16 이상을 제안한다. 판정불가 동안에는 기존 운영 계약을 유지한다.
3. 앞선 조건을 통과하고 후보 기술 실패가 현행 이하이며, 진행 정답 대응쌍에서 **현행만 과보류한 수 − 후보만 과보류한 수 ≥ 3**, 후보만 과보류한 수 ≤ 1이면 후보 채택을 권고한다. 비교는 유효하지만 개선 문턱을 넘지 못하면 현행을 유지한다.

호출 관측은 배정별로 대조한다. 신원 차단으로 0회, 같은 영수증 세 번 수신으로 실제 호출 1회, 종료 확인 뒤 적격 재시도로 실제 호출 2회인 세 배정은 합계만 보면 세 배정·세 호출이다. 합계만으로 배정당 단 한 번 호출됐다고 판정하면 안 된다.

최초·의미·복구의 마감 시각, 비용 상한, 표본과 문턱은 **첫 관련 실행 전 승인·동결할 제안값**이다. 16개의 합성 사례에서 오통과가 0건이어도 실운영 오류율이 0이라는 근거가 되지는 않는다.

## 개발 준비와 필요한 문서

- **오케스트레이터·런타임 담당**은 실제 참여자 원천, 기존 영수증으로 입증되는 필드, 호출이 시작됐다고 판정할 관측 지점을 먼저 대조한다. 인증 방식·키 관리·원장 보존 기간과 읽기 권한의 필요성을 기존 구현에서 확인하고, 새로 필요한 계약만 기능 명세로 남긴다.
- **평가 담당**은 과거 기록을 그대로 조회할 호환 표본, 거래 단위별 실제 호출 검출기, 미시작·미상의 재시도 표를 준비한다. 사례·정답과 최초 마감·대사 창을 동결한 뒤 실행한다.
- **개발 착수 전 결정 사항**은 표본·호출 예산과 수치 기준 승인, 변경할 레포 경계 확정이다. 이 설계에서는 모델 실행의 실제 단가나 소요 시간을 측정하지 않았다.

기획팀의 통합 제안, 전문 담당자의 원안과 배정별 네이티브 영수증 식별자는 [기획 결정 원본](planning-decision.json)에 있다. [공통 문서 정책](https://github.com/shakystar/agent-collaboration-lab/blob/112d4629d4261b4403ff33fbde43e36431c435f4/docs/documentation-policy.md)
