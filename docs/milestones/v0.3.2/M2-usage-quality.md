# M2 사용량 계약 품질 검토

11월 26일 M2 독립 검토에서 acl-014와 최종 판정자 acl-005는 고정 후보의 합성 인프라, 호환성과 두 업무 경로를 인수했다. 사용량 완전성은 별도 검증을 요청했다. 이 단계에서는 입력 경계에서 수치가 사라졌을 때 하위 모듈이 실측값을 만들 수 있는지를 확인한다.

## 코드 품질 검토 절차

1. 코드 작성에 참여하지 않은 검토자가 공통 개발 정책을 기준으로 후보 diff를 읽는다. 외부 입력을 해석하는 지점, 상태를 소유하는 모듈, 최종 판정에 필요한 도메인 이름과 테스트를 연결한다.
2. 발견 사항마다 관측한 입력, 기대 동작, 현재 동작과 재현 위치를 기록한다. 이번 건은 같은 세션·턴 식별자를 둔 독립 실행 세 개에서 마지막 사용량 알림만 바꿔 기준선을 확보했다.
3. 오케스트레이터가 변경 경계를 소유한 개발자에게 수정안을 배정한다. 검토자는 같은 합성 입력을 실제 브리지에 재생해 원문 영수증과 최종 판정을 대조하고, 기존 경로의 회귀 결과와 함께 독립 인수를 요청한다.

## 검증 경계

Go 어댑터에서 해당 턴과 마지막으로 일치한 알림의 세 정수 카운터가 모두 존재하고 음수가 아닐 때 측정값이 성립한다. Python에서 범위 표기가 없는 기존 합성 사용량은 비어 있으면 미확인으로 보류하고, 이후 같은 턴의 유효한 관측으로 보완할 수 있다. 완료한 턴 수와 사용량의 완전성은 별도로 판정한다.

| 합성 알림 | 기준 후보 영수증과 판정 | 수정 후보 기대값 |
|---|---|---|
| tokenUsage 객체에서 last 누락 | 세 값 0, verified | turn_usage 생략, uncertain |
| last에서 outputTokens 누락, 나머지 0 | 세 값 0, verified | turn_usage 생략, uncertain |
| 세 카운터 모두 명시적 0 | 세 값 0, verified | 세 값 0, verified |

기준 후보는 어댑터 f338b29, 런타임 4a457bb, 오케스트레이터 753fe02다. Go 담당 acl-006과 Python 담당 acl-007이 패치를 제출했다. 통합 시 새 Go 테스트의 패키지명을 실제 패키지명으로 맞추고 gofmt를 적용했다.

## 재현

M2 재현 환경에서 수정 후보의 브리지를 빌드하고 아래 명령을 세 저장소의 부모 디렉터리에서 실행한다. 각 상태 경로는 처음 사용하는 경로여야 한다. 도구는 각 단계의 네이티브 영수증 및 턴 식별자를 확인하고 같은 체크포인트를 다시 열어 추가 제출 여부를 검사한다.

```sh
milestones=agent-eval/docs/milestones
for mode in missing-last missing-counter zero; do
  python "$milestones/v0.3.2/reproduction/replay.py" --usage-case "$mode" \
    --bridge ./candidate-bridge --orchestrator ./role-orchestrator \
    --lab ./agent-collaboration-lab --fixture "$milestones/v0.3.0/cases/request-fixture.json" \
    --state "./quality-$mode" || exit 1
done
```

측정 범위는 마지막 일치 알림의 세 카운터다. 제공자의 내부 호출 수와 실제 청구액은 이 시험으로 확인할 수 없다.

## 독립 인수 결과

후보는 어댑터 007e055, 런타임 4a457bb, 오케스트레이터 571c53d다. 실제 영수증과 판정이 세 행의 기대값과 일치했고, 각 경우의 완료 턴 수는 1이었다. 요청 경로의 다섯 단계에서도 동일한 결과였다. 기존 체크포인트의 비영 사용량 영수증 다섯 건을 후보 브리지로 다시 읽었을 때 입력 10, 출력 3, 캐시 입력 2와 기존 영수증 해시가 보존됐다.

김가온(acl-014)은 첫 검토에서 실행물 식별자와 기준·후보 원본 근거를 요청했다. 동일 macOS 호스트의 바이너리 해시, 양쪽 영수증의 해시와 원문 필드, 기존 기록 재검증 결과를 보완한 뒤 김가온과 강이현(acl-005)이 차례로 수락했다. 최종 검토자는 후속 호출 수 시험에서 디스패치 직전의 중복 요청까지 계측하도록 제안했다. 이번 관측은 합성 peer의 새 턴과 영수증에 한정된다. [판정과 영수증 대조 기록](m2-usage-evidence.json)

Go 어댑터와 런타임은 각각 go vet 및 전체 race 테스트를 통과했다. 후보 브리지와 다시 빌드한 워크플로·프로브로 Python 회귀 160건을 실행해 실패와 건너뜀은 각각 0건이었다.
