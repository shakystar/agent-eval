# M1 증거 기반 평가 구현·검증

2026-11-20. M1의 저장 증거 등록→규칙 평가→재평가→비교 보고 경로를 구현했습니다. M2 의미 평가·사람 확정, M3 실행·주입, M4 두 번째 과제 묶음 검증은 미완료입니다.

## 결과

| 검증 | 결과 |
| --- | --- |
| 최종 Docker/Linux 이미지의 회귀 검사 | 20/20 통과, 실패·skip 0 |
| CLI 등록·가져오기·입력 투영·재평가·보고 | 8개 명령 통과 |
| 중복 보고서 출력 경로 | 덮어쓰기 거부 |
| M0 실제 Codex 저장 로그 | 2개 sample 가져오기·재평가 통과 |
| 실제 attempt ID와 원본 로그 해시 | 보존 확인 |
| 재가져오기 이후 실행 수 증가 | 0 |
| 새 모델 호출·재평가 중 프로세스 기동 | 0 |
| Windows 의존성 없는 코어 | 12개 통과; Inspect 검사 8개는 미설치로 제외 |

검증은 `--network none`에서 수행했습니다. 실제 로그 재사용 시 source volume은 읽기 전용이었으며 네트워크 연결과 프로세스 실행도 검사 코드에서 차단했습니다. M0 원본 모델 출력은 레포에 복사하지 않았습니다. 이번 실제 로그 검사는 nonempty 규칙으로 제품 연결을 확인한 것이며 문서 품질이나 평가 신뢰성 검증이 아닙니다.

## 범위와 한계

원본 저장소에는 native 이력 전체를 보존하고 제품 인덱스에는 최소 연결 정보만 둡니다. 공개 보고서는 원문·정답·규칙 값·오류 상세를 노출하지 않습니다. 내장 규칙은 산출물의 비어 있음·문자열 포함·JSON 값 일치 검사입니다. 임의 Python scorer, 의미 평가, native review를 사람 확정 판정으로 변환하는 기능은 제공하지 않습니다.

과제 미검토 상태와 M1의 draft 판정으로 성능 결론을 확정하지 않습니다. 예제의 baseline 계획 성공률 1/3과 판단 가능 범위 1/2는 분모 검증용입니다. 비용·토큰 누락을 0으로 보정하지 않습니다.

한 계획 슬롯에 실행 하나만 등록합니다. 재시도 선택·실제 실행 상태의 영수증 검증·주입은 M3에 남습니다. 동일 source의 다른 파일 표현은 원본별 해시를 보존하면서 중복 집계를 막지만, 다른 native ID를 가진 사실상 동일 실행을 자동 추론하지는 않습니다. 동시 다중 작성자와 강제 종료 복구는 검증하지 않았습니다.
