실제 모델은 기존 설정의 `gpt-6-astra`, reasoning `medium`을 사용했습니다. role-runtime JSONL bridge v1→codex-adapter→Codex 경로로 평가자만 실행했고 Inspect는 scorer/log API로 판정을 보존했습니다. 인간 기준 라벨은 grader 요청에 전달하지 않았습니다.

이 결과는 네 합성 calibration 사례의 측정입니다. 일반 직무 성능, 미공개 과제, 의미 평가기의 광범위한 신뢰성을 검증한 결과가 아닙니다. 실제 모델의 네 판정은 draft로 보존했으며 사람 기준과의 일치만으로 자동 확정하지 않았습니다. 사람 확정·정정·승인 철회 동작은 별도 합성 계약 검사로 확인했습니다.

## 사람 기준의 출처

사용자에게 합성 장애 인계 입력, 불확실성 보존 기준, A/C 충족·B/D 미충족 후보를 제시했고 사용자가 “과제·기준과 네 판정을 확인·승인합니다”라고 응답했습니다. 생성자가 독자적으로 만든 라벨을 사람 기준이라고 표시하지 않았습니다.

- [승인 질문의 입력·기준·후보와 실제 응답](../../examples/m2/approved-cases.json)
- [등록된 bundle](m2/bundle.json), [사람 기준 사례](m2/reference.json), [과제 승인 기록](m2/task-review.json)

같은 사용자가 과제와 기준 사례를 승인했습니다. 전문 평가자 패널이나 다수 사람 간 일치 검증은 수행하지 않았습니다. 기준 사례는 calibration으로 표시하며 validation 과제와 구분합니다.

## 최초 실패와 수정

첫 실제 실험 `/state/live-001`은 첫 사례만 완료했습니다. 두 번째 요청부터 bridge가 `conflict`를 반환했고 이후 요청을 자동 실행하지 않았습니다. 원인은 어댑터가 요청마다 trace ID를 새로 생성하여 bridge의 run/trace 고정 계약과 충돌한 것입니다.

trace ID를 실행 단위로 고정하고 요청별 span ID만 변경했습니다. 실제 Go fixture bridge의 순차 두 요청 회귀 검사를 추가해 통과시킨 뒤 새 실험 `/state/live-002`에서 네 사례를 모두 완료했습니다. 첫 실험의 부분 결과와 실패는 [별도 기록](m2/initial-live-failure.json)에 보존했습니다.

첫 실험에서 모델 채점 1건, 수정 후 새 실험에서 4건이 완료됐습니다. 충돌 요청은 모델 채점 전에 거부됐습니다. 자동 재시도·원래 과제 재실행은 없었습니다. 모델 토큰·금액은 이 어댑터에서 별도 계측하지 않았으며 0으로 간주하지 않습니다.
